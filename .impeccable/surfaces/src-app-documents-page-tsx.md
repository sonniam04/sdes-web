# Surface brief: คิวเอกสาร + ตรวจข้อมูล (Phase 1–2)

Mode: Operate. ผู้ใช้หลัก AP Clerk บน notebook จอเดียว 1366×768 ทำงานซ้ำทั้งวัน; AP Lead ใช้หน้าตรวจเดียวกันในโหมดอนุมัติ

## หน้า A: คิวเอกสาร (`src/app/documents/page.tsx`)
- งาน: อัปโหลด PDF ชุดจากอีเมล (1–50 ไฟล์) ดูผลรายไฟล์ ทำงานตามคิว กด "เริ่มตรวจ" เปิดใบแรกที่รอตรวจ
- โครง: แถบบน (เมนู), พื้นที่ลากวาง (ยุบเป็นแถบบางหลังอัปโหลด), แท็บกลุ่มสถานะพร้อมจำนวน, ตารางคิว (เลขที่ ผู้ขาย เลขใบกำกับ วันที่ ยอดรวม สถานะ เหตุผลบรรทัดเดียว)
- State: คิวว่าง, กำลังอัปโหลดรายไฟล์, ไฟล์ถูกปฏิเสธพร้อมเหตุผล (ซ้ำ → ลิงก์เอกสารเดิม), real-time, FAILED + อ่านใหม่, การเชื่อมต่อหลุด

## หน้า B: ตรวจข้อมูล split-view (`src/app/documents/[id]/review/page.tsx`)
- ซ้าย PDF (หน้า/ซูม, กรอบแดงบน field ที่ focus) ขวาฟอร์ม 4 หมวด: 1 ผู้ขาย (Tax ID ทีละหลัก 1-4-5-2-1), 2 ใบกำกับ, 3 รายการ 1–200 แถว + แถบผลรวมเทียบ Subtotal, 4 สรุปยอดชั้น 1 (ติ๊กรายบรรทัด ±0.01) และชั้น 2 (อัตรา WHT, ยอดจ่ายสุทธิ)
- แถบความเสี่ยงบนสุดของฟอร์ม, field confidence ต่ำมี % + เส้นใต้แดง, แถบปุ่มล่างติดตลอด: บันทึกร่าง / ยืนยันและไปใบถัดไป; โหมด AP Lead: อนุมัติ / ปฏิเสธ (ต้องมีเหตุผล) และแจ้งเมื่อห้ามอนุมัติเพราะเป็นคนแก้เอง
- คีย์ลัด: Tab ตามลำดับฟอร์ม, J/K จุดตรวจถัดไป/ก่อนหน้า, Ctrl+Enter ยืนยัน
- 1366×768: PDF 55% / ฟอร์ม 45% เลื่อนแยก; < 1280 px สลับแท็บ
- State: โหลด, PDF เปิดไม่ได้, AI อ่านไม่ได้, ยอดไม่ตรง, ผู้ขายใหม่, เลขใบกำกับซ้ำ, ถูกเปลี่ยนโดยผู้อื่น (409)
